# Navigation prototype outcomes

- [x] **Route preview from an eligible real listing:** From an eligible non-demo property detail, a client can explicitly start a driving route from the device's current location to the listing's allowed coordinates. The route is requested from OSRM over HTTPS, displayed as a road polyline on the in-app map, and includes distance, estimated duration and a next-maneuver cue. The client can hand off to Google Maps (Android/web) or Apple Maps (iOS) for full turn-by-turn voice guidance.
- [x] **Location privacy and platform permissions:** The app does not request location at startup, does not persist location history, and does not request background location. It asks for foreground location only after the client starts the route and explains that the origin and destination are sent to the public OSRM prototype service.
- [x] **Location provenance safeguards:** Fictional sample listings cannot start navigation. Unverified or invalid coordinates cannot be routed. Approximate coordinates are clearly described as generalized area/meeting-point pins, not exact property entrances, and require client acknowledgement before routing.
- [x] **Failure and recovery:** Denied/unavailable location, route-service errors, malformed/no-route responses and failed external-app handoff produce recovery feedback without displaying coordinates or crashing. Automated tests exercise the deterministic permission, parser and page-state paths without using real location or network access.
- [x] **Prototype boundaries:** Route-source attribution is visible. Documentation states that the public OSRM demo has no availability guarantee and must be replaced with a selected/self-hosted routing provider before public launch. No production migration, deployment, paid account or store release is performed.
